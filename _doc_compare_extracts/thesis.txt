摘  要
为提高旅游景区信息查询、路线选择和在线咨询的便捷性，本文设计并实现了一款基于 Spring Boot 的旅游景点与路径推荐系统。系统后端采用 Spring Boot 实现业务接口，前端采用 Vue.js 完成页面交互，并通过 Spring Data JPA 对用户、景区、景点、旅游套餐、购物车和路线记录等数据进行管理。系统面向普通用户和管理员两类角色，用户端实现注册登录、景区浏览、路径推荐、智能咨询、套餐查看、购物车管理和个人信息维护等功能，管理员端实现用户管理、景区资源维护、套餐信息维护和基础数据管理等功能。其中，路径推荐模块结合用户出行偏好、景点评分和景点连接关系，采用 Dijkstra 算法计算可达路线；智能咨询模块使用 LangChain4j 接入大语言模型，并结合系统已有景区和景点信息生成咨询回复。测试结果表明，系统主要功能运行正常，达到功能设计要求，能够为用户查询景区信息和选择游览路线提供一定支持。
关键词：智慧旅游；Spring Boot；个性化推荐；路径规划；智能问答
Abstract
In order to make it more convenient for users to query tourist attraction information, choose travel routes and ask questions online, this paper designs and implements a tourist attraction and route recommendation system based on Spring Boot. The backend of the system uses Spring Boot to build business interfaces, the frontend uses Vue.js for page display and user interaction, and Spring Data JPA is used to manage data such as users, scenic areas, scenic spots, tour packages, shopping carts and route records. The system is mainly used by ordinary users and administrators. Ordinary users can register and log in, browse scenic areas, get route recommendations, use intelligent consultation, view tour packages, manage shopping carts and maintain personal information. Administrators can manage users, scenic resources, package information and basic data. In the route recommendation module, the system considers user travel preferences, scenic spot ratings and the connections between scenic spots, then uses Dijkstra's algorithm to calculate reachable routes. In the intelligent consultation module, LangChain4j is used to connect the large language model, and the existing scenic area and scenic spot information in the system is used when generating replies. The test results show that the main functions of the system can run normally and basically meet the design requirements, which can provide some support for users when they query scenic information and choose travel routes.
Key words: smart tourism; Spring Boot; personalized recommendation; route planning; intelligent question answering
引言
背景与意义
随着旅游业的发展和游客出行需求的增加，越来越多的用户习惯通过网络平台查询景区信息、规划游览路线和购买旅游套餐[1][7]。相比传统线下咨询方式，线上旅游服务能够为用户提供更加便捷的信息获取渠道[1]。但在实际使用过程中，旅游信息往往分散在不同平台，用户需要反复查找景区介绍、景点位置、路线安排和套餐内容，路线选择也多依赖人工比较，容易增加出行规划成本[2][11]。特别是在景区景点较多、景点之间存在不同连接关系的情况下，用户很难快速选择较合适的游览路线[4][5]。
目前，部分旅游平台虽然能够提供景区展示和套餐浏览功能，但在个性化路线推荐和在线咨询方面仍存在不足[2][3][14]。一方面，普通路线查询更多依赖固定路线或简单筛选，难以结合用户出行偏好、景点评分和景点之间的连接关系进行综合推荐[5][6]；另一方面，在线咨询如果缺少对平台已有景区资源的结合，容易出现回复内容与实际景区信息不一致的情况，影响用户获取信息的准确性[15][16]。因此，有必要设计一套集景区信息展示、路径推荐、旅游套餐管理和智能咨询于一体的旅游景点与路径推荐系统。
本文设计并实现的基于Spring Boot的旅游景点与路径推荐系统，能够对景区、景点、套餐和路线等信息进行统一管理，为用户提供景区浏览、路线推荐、智能咨询、套餐查看和购物车管理等功能，同时为管理员提供景区资源维护和基础数据管理支持[9][10]。系统通过 Dijkstra 算法为用户提供路径选择参考，并结合 LangChain4j 接入大语言模型实现旅游咨询服务[15][16]。该系统的设计与实现有助于提高旅游信息查询和路线选择的便捷性。
国内外研究现状
移动互联网、在线支付、地图定位和景区数字化服务的发展，改变了游客查找旅游信息的方式。旅游平台也逐渐由景区介绍的发布窗口，转向行程组织、路线筛选和服务咨询的入口。张鞠成等对智慧旅游研究进行梳理后指出，相关研究主要集中在概念内涵、技术支撑、应用场景和评价体系等方面，也说明旅游信息服务在资源整合和智能支持方面仍有改进空间[1]。在实际出行准备中，游客常常需要分别查看景区官网、地图软件、在线旅游平台和用户评价，才能了解开放时间、门票套餐、景点距离和游览建议等信息，检索过程较为分散。李雅美和王昌栋的研究表明，基于标签的个性化推荐有助于提高用户兴趣与旅游资源的匹配程度；Ricci关于旅游推荐系统的研究也说明，推荐系统能够辅助游客选择目的地、景点和相关服务[2][11]。因此，将景区展示、路线计算和咨询服务放在同一系统中，能够减少游客前期规划的时间成本。
在线旅游用户规模不断扩大后，游客对个性化出行服务的要求也随之提高。已有研究表明，旅游推荐不能只按照景点热度或单一评分排序，还需要考虑用户群体差异、出行时间、兴趣变化和景区之间的空间联系[3][4][5]。同时，李晓旭等关于轨迹模式挖掘的研究表明，游客行为轨迹可以为路线推荐提供参考[6]；Adomavicius和Tuzhilin的研究也指出，用户理解不足和上下文利用不充分，是推荐系统中较常见的问题[12]。因此，旅游推荐系统需要把景点属性、用户偏好、路线可达性和出行限制联系起来，不能只给出简单的景点列表。
在行业应用中，智慧旅游已经涉及了景区展示、在线购票、客流监测、电子导览和平台运营等环节。Gretzel等认为，智慧旅游建立在信息通信技术与旅游服务生态的基础上；Buhalis和Amaranggana强调，智慧旅游目的地应使用智能技术提升个性化服务水平；Li等则指出，智慧旅游应为游客决策提供支持[7][8][9]。但在一些中小型旅游平台中，前台展示、后台维护、路线推荐和智能咨询之间仍存在分离现象。如果后台数据只做静态维护，景区开放状态、套餐内容和资源更新就难以及时传递到用户端，游客仍需要自己判断行程安排。Neuhofer等的研究说明，页面交互与智能服务结合后能够改善游客体验[10]。因此，在同一平台中组织资源维护、页面交互和推荐计算，是提升旅游服务连续性的基础。
在推荐方法方面，个性化旅游推荐已经形成协同过滤、知识图谱、序列模式挖掘和混合推荐等多种思路[11][12][13][14]。这些方法可以改善兴趣匹配和路线组织效果，但在具体开发中，还有许多问题要处理。Lewis等提出的检索增强生成方法说明，知识密集型任务可以通过外部知识检索提高结果可靠性[15]，Li等关于生成式人工智能在旅游管理中的研究也指出，旅游智能服务仍需解决可信生成和场景适配等问题[16]。
综上，本文选择 Spring Boot、Vue、MySQL、Spring Data JPA、路径规划算法和LangChain4j开发框架作为主要技术基础，完成了旅游景点与路径推荐系统的设计与实现。

相关开发技术
Spring Boot与后端分层
Spring Boot是在Spring框架基础上发展起来的Java Web应用开发框架，它具有自动配置、启动较快和配置相对简单等特点。和传统Spring项目相比，Spring Boot可以减少很多XML配置，开发人员在编写项目时，可以把更多精力放在业务功能实现上。
在后端开发中，分层架构是一种比较常用的代码组织方式。系统一般可以分为控制层、业务层、持久层和实体层。控制层主要接收前端请求并返回处理结果；业务层主要处理系统中的具体业务逻辑；持久层负责和数据库进行数据交互；实体层用来描述数据对象及其关系。通过这种分层方式，代码之间的联系会相对清楚，后期维护和功能扩展会方便一些。
Vue与前端交互技术
Vue是一种JavaScript前端框架，主要用于构建用户界面和单页面应用。Vue支持组件化开发，可以把一个页面拆分成多个组件，这样前端代码在组织和复用时会更加方便。Vue还具有数据驱动的特点，当数据发生变化时，页面可以根据数据自动更新，减少了直接操作DOM的复杂程度。
在前后端分离开发模式下，Vue通常会通过Axios等HTTP请求工具和后端接口进行交互。前端页面向后端发送请求，后端把JSON格式的数据返回给前端，前端再根据返回的数据完成页面展示。前端主要负责页面显示和用户操作，后端主要负责数据处理和业务逻辑，两部分通过接口连接起来。
JPA持久化技术
JPA是Java Persistence API的简称，是Java平台中的对象关系映射规范。主要用于解决 Java 对象与关系型数据库之间的数据映射问题。JPA可以通过注解或配置的方式建立实体类与数据表之间的对应关系，使开发者能够以面向对象的方式完成数据持久化操作。
路径规划算法
路径规划算法主要用于在多个节点之间寻找一条符合要求的通行路线。在路径规划算法中，Dijkstra算法是一种较为常见的最短路径算法。Dijkstra算法适合处理节点数量适中、边权明确的路径规划问题。
LangChain4j开发框架
LangChain4j是面向Java生态的人工智能应用开发框架，主要用于帮助Java项目更方便地接入大语言模型能力。它对模型调用、提示词组织、上下文管理、工具调用和知识检索等能力进行了封装，使开发者可以在Java后端中以较统一的方式构建智能问答、文本生成和知识增强应用。

非功能需求分析
（1）安全性需求。系统存在用户和管理员两类角色，用户和管理员在访问系统相关功能前应完成身份验证，身份验证通过后才可以进入对应页面。
（2）可靠性需求。系统需要能够较稳定地处理用户和管理员的基本业务流程。用户在登录、浏览景区等操作过程中，系统应保持正常响应；当出现账号不存在、景区信息缺失、路线无法推荐等情况时，系统应给出清楚提示，而不是直接中断运行。管理员在维护景区、套餐和用户信息时，系统也要保证操作结果基本准确，尽量避免数据混乱或信息丢失。
（3）易用性需求。系统面向普通旅游用户和平台管理员，页面操作应尽量简洁明了。用户端应突出景区浏览、路线推荐、智能咨询和购物车等常见功能，使用户能够快速找到所需入口，减少不必要的操作。管理员端应突出信息管理效率，使管理员能够方便地完成查询、新增、修改和删除等管理操作。
（4）兼容性需求。系统以Web形式运行，在主流浏览器中具有基本一致的访问效果。不会因浏览器差异出现明显错位或功能异常，以免影响用户浏览和管理员维护操作。
系统设计
系统总体架构设计
如图4所示，系统采用前后端分离的分层架构，整体由展示层、业务接入层、核心业务服务层和数据存储层组成。各层之间通过明确的调用关系进行协作，从而降低页面展示、业务逻辑和数据存储之间的耦合度。
图4 系统总体架构图
展示层基于Vue实现。负责系统页面组织、路由跳转、数据请求和结果展示。前端通过Axios向后端RESTful API发送请求，实现用户端和管理端页面的统一展示与交互。
业务接入层是前端与后端之间的接口入口。主要负责接收前端请求、进行身份校验、参数传递和接口转发。该层通过RESTful API对外提供服务，并使用JWT完成访问控制与请求安全处理，保证前后端通信过程的规范性和安全性。
核心业务服务层基于Spring Boot实现，是系统业务处理的主要部分。该层接收业务接入层传入的请求，根据业务规则完成相应的数据处理、逻辑计算和结果封装，并将处理结果返回给前端展示层。
数据存储层用于支撑系统的数据持久化和文件访问。系统使用MySQL保存业务数据，通过JPA完成常规数据访问，并在部分场景中使用JDBC进行查询处理；同时，本地文件存储用于保存上传图片资源。

推荐模型结构定义
为提高推荐结果的合理性，本系统将旅游景点与路径推荐问题抽象为一个多属性决策与路径搜索相结合的问题。多属性决策部分用于判断候选景点与用户需求的匹配程度，路径搜索部分用于在多个景点之间寻找综合代价较低的游览路线。该模型主要包含目标层、准则层和方案层三个层次。
（1）目标层：形成符合用户需求的旅游景点与路径推荐方案。目标层是推荐模型最终想得到的结果，也就是在满足用户出行条件的基础上，选择比较适合用户偏好的景点，并给出相对合理的游览顺序和路线方案。推荐结果既要有一定个性化，也要保证路线能够到达、推荐理由能够合理说明，不能只按照热门程度或单一距离进行排序。
（2）准则层：影响推荐结果的主要评价因素。结合本系统的实际业务，准则层主要包括以下几个方面：
1）兴趣匹配程度。该因素用来判断景点类型和用户偏好是否接近。例如，用户表达自然风光、人文历史、亲子游、拍照打卡、休闲游览等需求时，系统会优先考虑拥有相关特征景点。
2）景点综合吸引力。该因素主要反映景点本身的受欢迎程度、历史评价和内容完整情况。综合吸引力较高的景点，在推荐排序中会有一定优势。
3）出行成本与时间成本。该因素主要考虑用户到达景点以及完成游览所需要的距离、时间和费用。当用户强调“最近”“最快”“省钱”等需求时，系统会提高这些因素在推荐过程中的影响。
4）游览舒适度。该因素主要考虑体力消耗、拥挤程度、休闲程度，以及是否适合老人、儿童等同行人群。当用户提出“带老人”“不想太累”“亲子出行”等需求时，系统会降低游览强度较高或拥挤程度较高景点的推荐优先级。
5）路径可达性。该因素用来判断景点之间是否存在有效连接，以及路线是否适合连续游览。对于不能形成合理游览顺序，或者路径代价过高的候选方案，系统会降低其排序，必要时也会进行过滤。
（3）方案层：候选景点与候选路径集合。方案层由系统中满足基本条件的景区和路线组合构成。对于单点推荐，候选方案主要表现为不同景点的排序结果；对于路径推荐，候选方案则表现为由起点、若干中间景点和终点组成的游览路线。系统根据用户输入条件和准则层指标，对候选方案进行计算和排序，然后把最终推荐结果返回给用户。

路径规划算法设计
完成候选景点筛选后，系统还需要计算景点之间的游览路线。旅游路线以带权图表示，其中景区、景点或关键位置可以看作节点，景点之间能够通行的关系可以看作边，边权表示两点之间的综合通行代价。根据用户选择的推荐模式，边权可以主要体现空间距离，也可以主要体现预计耗时，还可以把个性化偏好一起考虑进去。

路径规划算法的主要作用，是根据用户出行需求和景区之间的可达关系，计算出比较符合用户偏好的旅游路线。算法输入主要包括用户出行条件、候选景点集合、景点之间的连接关系以及偏好权重；算法输出主要包括推荐路线、路径综合代价、推荐景点顺序和推荐理由。
路径搜索部分采用Dijkstra算法。算法从起点开始，先选取当前累计代价最小的节点，再更新它相邻节点的路径代价，直到得到目标节点的较优路径。该算法步骤比较清楚，结果也相对稳定，适合用于本文系统中景点数量适中、连接关系较清晰的路线推荐场景。通过重新定义边权，系统可以支持最短距离、最短时间和个性化综合路线等推荐方式。

智能问答流程设计
智能问答功能用于接收用户输入的自然语言问题，并结合系统已有旅游资源生成咨询回复。用户在使用系统时，可能会输入“开封有哪些适合老人去的地方”“我想找一条适合拍照且不太累的路线”“预算低一点怎样安排”等问题。与普通关键词检索不同，智能问答需要对用户问题中的出行意图、兴趣偏好和约束条件进行理解，并尽量围绕系统中已有的景区、景点和套餐信息进行回答。
本系统知识库设置为本地数据库里的旅游基础数据。旅游基础数据包括景区、景点、门票套餐、公共设施、图片资源和地理位置等信息。通过LangChain4j接入deepseek的api，实现用户问题与模型之间的交互。处理流程主要包括用户问题接收、业务范围判断、资源信息组织、模型调用和结果返回几个步骤。首先，前端接收用户输入的问题，并将问题提交至后端智能问答接口；后端接收到请求后，判断问题是否属于景点推荐、路线规划、套餐咨询或旅游信息查询等业务范围。对于明显超出旅游业务范围的问题，系统返回提示信息，避免生成与系统无关的回答。
对于符合业务范围的问题，系统会从数据库中查询相关景区、景点、套餐和路线信息，并将这些内容整理为可供模型参考的上下文信息。随后，后端通过LangChain4j将用户问题、平台已有旅游资源信息和回答要求共同发送给deepseek，由模型生成咨询回复。回答要求中会限制模型尽量使用系统已有的景区和景点信息，不随意编造平台中不存在的旅游资源。模型返回结果后，系统将回答内容传回前端页面进行展示，供用户作为景区选择和路线规划的参考。如图7所示。

智能问答结果生成与约束处理
智能问答结果生成主要依赖LangChain4j对deepseek的api调用。用户提交旅游咨询问题后，系统会先判断问题是否属于景区查询、路线咨询、套餐咨询等业务范围，再从数据库中提取相关景区、景点、套餐等信息，作为大语言模型生成回答的参考内容。随后，系统将用户问题、相关旅游资源信息和回答要求共同组织成提示内容，并通过LangChain4j提交给deepseek，由模型生成面向用户的咨询回复。
为减少回答内容与系统数据不一致的情况，系统在生成回答时对内容范围进行约束。一方面，提示内容中明确要求模型优先依据系统提供的景区、景点和套餐信息进行回答，不随意推荐平台中不存在的旅游资源；另一方面，系统对模型返回内容进行简单校验，对于明显超出旅游业务范围或与平台资源无关的内容，不作为有效回答直接展示。通过这种方式，智能问答功能能够在利用大语言模型理解自然语言问题的同时，使回答内容尽量围绕系统已有旅游资源展开。问答意图识别提示词如图8所示，问答事实润色提示词如图9所示。

结论与展望
本文围绕提高旅游景区信息查询、路线选择和在线咨询的便捷性，设计实现了基于Spring Boot的旅游景点与路径推荐系统设计与实现。系统采用前后端分离架构，后端基于Spring Boot 和Spring Data JPA完成业务接口与数据持久化，前端基于Vue实现用户端和管理员端页面交互。在核心功能上，采用 Dijkstra 算法计算景点之间的可达路线，进行路径推荐；智能问答模块通过 LangChain4j 接入deepseek大语言模型，咨询回复进行生成。通过功能测试，系统的景区浏览、路线推荐、智能咨询等功能能够正常运行，达到系统设计要求。
尽管本系统已经完成了旅游景区信息查询、路径推荐和智能问答等主要功能，但路径推荐对实时交通、天气、景区开放状态和客流情况等动态因素考虑还不够充分，未来可进一步引入相关数据，提高路线推荐结果的实用性，智能问答模块虽然能够结合系统已有景区和景点信息生成咨询回复，但在上下文理解和结果校验方面仍有待完善，未来可继续优化问答范围控制和回复质量，减少回答内容与平台资源不一致的情况。
